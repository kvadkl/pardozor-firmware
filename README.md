# ПарДозор — прошивки

Официальные пользовательские выпуски **ПарДозора — автоматика и контроль**.

[Скачать прошивку](https://github.com/kvadkl/pardozor-firmware/releases) · [Изменения по версиям](CHANGELOG.md) · [Инструкция](https://kvadkl.github.io/pardozor-manual/)

## Первый выпуск — 0.5.0

Нумерация продолжает проект по правилам SemVer: `MAJOR.MINOR.PATCH`. Версия **0.5.0** — начальный выпуск этого публичного репозитория для ПарДозора P1. Новые функции увеличивают MINOR, совместимые исправления — PATCH, несовместимые изменения — MAJOR.

Здесь публикуются только проверенные пользовательские версии, отдельно разрешённые автором к выпуску. Внутренняя разработка и тестовые сборки сюда не выкладываются. Сборка или успешный запуск тестов сами по себе не разрешают публикацию следующей версии.

## Совместимость

Только **ПарДозор P1 на YD-ESP32-S3 N16R8**: ESP32-S3, 16 МБ Flash, 8 МБ PSRAM, штатная таблица разделов с двумя OTA-слотами по 6,25 МБ. Не подходит для ESP32-WROOM-32, ESP32-S3-Zero и произвольных плат ESP32.

`pardozor-0.5.0.bin` — образ приложения для обновления, **не полный дамп Flash и не пакет первичной прошивки пустой платы**. Не записывайте этот файл по адресу `0x0`.

## Установка из файла

1. Скачайте `.bin` из [публикации 0.5.0](https://github.com/kvadkl/pardozor-firmware/releases/tag/v0.5.0).
2. Завершите процесс. Снимите температурный контроль со всех каналов, выберите этап с режимом клапана **«Всегда закрыт»**, верните управление этапу и дождитесь сохранения настроек.
3. В веб-интерфейсе прибора откройте **«Обновление прошивки»**, выберите файл и нажмите **«Загрузить прошивку»**.
4. Не отключайте питание до завершения записи и перезапуска. Затем проверьте версию и настройки. После запуска клапан закрыт; автоматику выбирает оператор.

Обновление приложения не стирает настройки, калибровки и раздел журналов. Нужные журналы всё равно рекомендуется заранее экспортировать.

## Обновление через интернет

В 0.5.0 доступна проверка следующих пользовательских выпусков непосредственно с GitHub:

1. Подключите прибор к Wi-Fi с интернетом. Резервная точка доступа самого прибора интернета ему не даёт.
2. Откройте **«Обновление прошивки» → «Проверить обновления»** и прочитайте описание новой версии.
3. Остановите процесс, снимите контроль со всех датчиков, выберите закрытый этап, верните управление этапу и дождитесь сохранения настроек.
4. Нажмите **«Установить обновление»** и подтвердите установку. Не отключайте питание во время записи.

Для HTTPS нужна корректная дата; страница обновления при необходимости синхронизирует её с браузером. Файл скачивается в PSRAM, проверяются его размер, SHA-256, плата и идентификатор приложения, затем записывается неактивный OTA-раздел.

**Автоматической установки нет.** Открытие страницы не запускает даже проверку GitHub. Устанавливается только более новая пользовательская версия; равная и более старая версии из интернета не предлагаются. При совпадении установленной и опубликованной версии неактивная кнопка установки — штатное поведение.

Каталог `latest.json` содержит только опубликованный пользовательский выпуск. Если прибор ещё не умеет проверять GitHub, сначала установите 0.5.0 вручную. Ручная загрузка остаётся доступна без интернета. Обычная работа прибора не требует GitHub, облака или аккаунта.

## Файлы выпуска

- `pardozor-<версия>.bin` — приложение для Web OTA;
- `SHA256SUMS.txt` — контрольная сумма;
- `manifest.json` — версия, совместимость, размер, хеш и описание.

Проверка в PowerShell: `Get-FileHash .\pardozor-0.5.0.bin -Algorithm SHA256`. Значение должно совпасть с `SHA256SUMS.txt` из той же публикации.

Исходники закрытого проекта, настройки Wi-Fi, дампы Flash, персональные данные и внутренние материалы испытаний здесь не публикуются. Бинарные файлы находятся во вложениях Releases, а не в истории Git.

ПарДозор не управляет нагревом и не заменяет оператора. Не обновляйте прибор во время перегонки. Автоматический откат после неудачного запуска новой версии не гарантируется.
